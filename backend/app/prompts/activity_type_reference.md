Each learning activity is one of these types. Use these definitions and frequency rules when deciding which types to use, how many, and where:

- **reading**: guided explanatory content teaching one concept or section of the module. The majority of a module's content should be readings — but interleave them with other activity types rather than stacking several in a row.
- **video**: an embedded instructional video. Handled separately, outside this planning step — never plan a "video" activity yourself.
- **quiz**: a short knowledge check (1 to 3 questions) on something specific just covered, typically right after the reading(s) it checks. At least 2 quizzes across the whole course. Spread them across different modules when there's more than one module — a single-module course needs 2 quizzes within that one module instead.
- **assessment**: the course's single closing knowledge check (10 to 15 questions) covering material from across the whole course, not just one module. Exactly one per course, and always the very last activity of the very last module — never anywhere else, never in any other module.
- **essay**: a short written prompt asking the learner to explain, compare, or reflect on a concept in their own words, reviewed with real feedback. At least one per course.
- **discussion**: a back-and-forth conversation with Bonsai about a course concept (multiple exchanges, not a single question). Exactly one per course.
- **project**: a hands-on task (a coding exercise, a DIY task, or similar) with a clear goal, any needed requirements/materials, and step-by-step instructions — only plan one if this course's subject genuinely suits hands-on work. At least one per course when it does, and only within the last two modules.
- **capstone**: a larger optional hands-on project combining skills/knowledge from across the whole course — only for courses whose subject is a hands-on skill worth practicing at scale. When used, it's the course's finisher: place it in the final module, before the closing assessment.

Never more than one of essay, project, discussion, or capstone in the same module — each is substantial enough that stacking them overloads a single module.

A module's activities should read in a sensible order: e.g. a reading before the quiz that checks it, not after.

The per-module counts above (how many readings, whether a module gets a quiz) can flex for a short course with few modules. The once-per-course items cannot — always include exactly one assessment and exactly one discussion somewhere in the course, and at least 2 quizzes total, even in a course with only 1 or 2 modules. If the course has only one module, that module alone must still end with the assessment (after its quiz(zes)/essay/discussion/project, if any), and still needs a discussion and at least 2 quizzes fit into it somewhere.
